# AEL evidence continuity and measured reuse proposal

## Origin

Cross-project audit and source assessment on 2026-09-29, source revision `2dc0f5e`. The user requested analysis of registered-project records, assessment against AEL assumptions, and specifications with execution plans based on the findings.[^evidence]

## Problem

The retained corpus does not establish an automatic path from operations to reusable, verified knowledge. Installed artifacts differ, resumed events can be absent from learning, result facts are incomplete, and operational candidates are separate from retrievable knowledge. Existing components need explicit integration and qualification before the value of reuse can be measured.

Historical counts and controlled reproductions are distinct evidence classes. They do not prove that every installation gap has one cause, that no-result means failure, or that any specific native host envelope contains an exit code.[^evidence]

## Proposed outcome

An installed artifact is identifiable; eligible legacy and resumed operations reach one bounded logical reader; missing analysis and delivery have recoverable explicit states. Scoped instruction and typed task evidence feed an inspectable candidate lifecycle. An explicitly enabled pilot uses eligible knowledge in a subsequent session with independently recorded delivery, application and task result.

## Category

Architecture, tooling, knowledge lifecycle, developer experience and documentation.

## Expected effect

The package is intended to reduce missed analysis, repeated attempts without new evidence, incorrect scope and repeated work in later sessions. The effect remains unmeasured until a frozen baseline and paired public-path runs exist. Lesson count alone cannot demonstrate benefit.

## Scope

Eight delivery units cover the existing local TypeScript/SQLite implementation and one default-off Codex reuse pilot. Existing registered projects supply audit context, not blanket authorization to modify all their installations. Full cloud/SSO and cross-agent M7–M9 work remains separate.

## Requires full specification?

Yes. Executable behavior, persistent formats, source qualification, lifecycle integration and the proposed delivery dependency change require reviewed contracts. Eight Draft specs and matching proposed plans are linked in the delivery index.[^package]

## Decision

Proposed. Specifications and plans were prepared together at the user's request. No implementation approval, migration, recovery replay or pilot activation is recorded.

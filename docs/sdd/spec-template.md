# Specification template

## Status

Draft | In review | Approved | Superseded

## Problem

Describe the observed problem and why it deserves a durable change.

## Evidence

Reference sessions, findings, lessons, benchmark cases or repository facts.

## Goals

List measurable outcomes.

## Non-goals

State what this change intentionally does not solve.

## User-visible behavior

Describe the contract from the developer/agent perspective.

## Architecture and boundaries

Define affected components and interfaces without implementation detail.

## State and lifecycle

Describe state transitions and invariants when applicable.

## Failure behavior

State fail-open, fail-closed and degraded-mode semantics.

## Privacy and security

State data handling, sanitization and external-provider constraints.

## Compatibility and rollout

Describe migration and backward-compatibility expectations.

## Acceptance criteria

Define observable behavior and regression cases.

## Open decisions

Only unresolved decisions that block approval. Approved specs must not retain unresolved placeholders.

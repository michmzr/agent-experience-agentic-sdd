# Team workflow

## Shared rules

The team reviews durable knowledge changes like documentation changes. A merged entry may affect every supported coding agent, so reviewers should check scope and evidence carefully.

## Personal profiles

Developers may choose local per-repository/workspace profiles such as `learning` without changing team policy. Learning mode disables hard blocking locally but keeps warnings and evidence capture active.

## Knowledge promotion

Project facts supported by repository/tool evidence may be promoted automatically under policy. Pure user preferences and new reusable skill candidates require explicit approval. Task-specific instructions stay local to the task.

## Review workflow

When recurring friction is suspected, a developer manually runs a deep session review with the source tool declared. The resulting local analysis may propose shared lessons or project improvements. Behavior-changing proposals enter SDD and require human approval before implementation.

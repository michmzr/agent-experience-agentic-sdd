# AVB real-trial scaffold, 2026-10-01

## Observable contract

The new `package-manager-fact` B2 scenario creates a Git repository with a tracked `packages/app/package.json` containing `pnpm@12.6.0`. The task asks the agent to write `pnpm\n` to `packages/app/answer.txt` and check the chosen manager with `--version`. The checker compares exact file bytes, requires a successful observed `pnpm --version` command, rejects other repository files, and detects changes to Git metadata. The first package manifest read in session B is required validation. Only a second consecutive successful exact read with identical bounded JSON output counts as redundant; agent prose between reads does not reset that comparison. A file change or another command does.

The v2 paired protocol fixes five randomized pairs, the scenario revision and fixture digest, model `gpt-6-sol`, Codex CLI version `0.157.1`, its qualified binary SHA-256, sandbox `workspace-write`, approval `never`, build identities, budgets, and the reviewed A-session seed-store digest. The current A source path runs two separate verified Codex children, requires an exact successful read of the tracked package manifest followed by a separate successful `pnpm --version` from each trusted CLI JSON stream, records the operations in the public experience store, reviews the candidate through the public CLI, and verifies the package fact from the tracked file. The seed is copied into an advice slot. Its retrieval context uses the actual B Codex thread ID, and the same child must expose a response-only challenge, select through the public CLI, and perform an operation linked to the reviewed signature. The deterministic task checker is separate from AAP `outcome-observed`.

A second, separately labeled disabled diagnostic used the same synthetic Git fixture and a prompt that explicitly required shell commands. `rtk proxy node /private/tmp/avb-disabled-diagnostic.mjs` exited 0 after 28,403 ms with a completed Codex turn and 17 parsed JSONL events.

# AAP live exposure qualification

## Observable target

Qualify `delivered` only when an independently observed host event binds the exact bounded advice response to the invocation, bundle and session after the response is available to the agent. Keep `agent-claim` distinct. A failed, truncated or missing observation remains unsupported. This is the AAP-A3/A4 gate for a controlled Codex session B, not a requirement to infer model comprehension.[^aap]

## Source audit

The public `ael advice retrieve` path records `retrieved` before returning a bounded CLI response. The public usage path accepts `delivered` only as `agent-claim`. The store rejects new `cli-output` delivery facts, and legacy rows of that origin cannot authorize later stages. Focused tests already cover those boundaries.[^implementation]

The installed Codex CLI reports version `0.157.1`. Its `exec --json` option emits JSONL events. The current project hooks include `PostToolUse`, whose documented input has `tool_use_id`, `turn_id` and `tool_response`. That hook runs after a tool produces output, before Codex continues with the model. Codex can use later hook feedback as the model-visible result, including a blocked original result. Therefore observing `tool_response` or a completed CLI process is not a final exposure witness.[^host]

Codex documents `transcript_path` as a convenience path whose format is not a stable hook interface. Its `exec --json` item events are suitable for checking executed commands, but the published event example does not specify a final model-input acknowledgement for a particular tool response. Neither source supplies the missing exposure contract.[^stream]

The Codex review adapter reads an explicitly supplied JSONL file and accepts synthetic records. It does not retain a tool call identifier with normalized `function_call_output`, nor does it preserve structured output. Such a file is not a trusted source of actual agent exposure. It cannot be promoted to `delivered` by matching text or timestamps.[^adapter]

The related AEC qualification ran isolated Codex CLI probes. The first exited before any tool invocation with a bounded `model` diagnostic. A `gpt-6-sol` probe later emitted three `command_execution` start/completion pairs with stable item IDs and exit codes; the temporary project hooks still emitted zero events. The probe retained neither command text nor output text, and it did not invoke advice retrieval. It therefore provides no delivery witness for AAP. This audit did not initiate a separate model invocation.[^probe]

## Nonce challenge assessment

An unpredictable marker generated only with the advice response and later present in an independently captured Codex action could show that the agent had access to that marker. The official Codex JSON event definition includes `thread.started.thread_id` and `command_execution` item ID, command, aggregated output, status and exit code. The observed event pairs support the item lifecycle, but this probe did not retain the text fields, so it does not yet validate the proposed marker chain.[^event-schema]

The minimum controlled check would run the public `ael advice retrieve` in an isolated Codex CLI session and then have the agent issue a separate command containing a marker generated only in that response. A bounded harness would check the same thread, successful completed retrieval with bundle and marker, a later started command containing the marker, no intervening source for that value, and completed turn. It would discard raw command output after deriving sanitized evidence. This could qualify possession of a marker in that one session; it would not establish model comprehension, general Codex delivery or AAP-A4 application and result. An `advice record` declaration or user-supplied JSONL remains insufficient.

The existing public AAP path cannot supply that marker without changing its response contract. In the controlled AAP test, a verified convention is tied to `AGENTS.md`, and a project fact to a Git-tracked `package.json`. A random marker inserted into either source would be in an agent-readable file. Inserting it only into the candidate statement would leave the added text unsupported by the underlying evidence. The retrieval input and local SQLite store are also readable by an agent running under the same file permissions. A marker derived from them would not isolate exposure to the response. No fixture-only nonce challenge meets the stated condition, so no paid run is proposed for that design.[^controlled]

## Decision

At this checkpoint, live Codex delivery remained `unsupported`. The existing `retrieved` and `agent-claim` facts remained available with their distinct origins. AAP-A4 and AVB B2 could not treat either as observed delivery. The next qualification step was a controlled host run that captured a later trusted challenge response with the bindings above. This preserved a single AAP usage store and avoided a second delivery channel with unsupported semantics.

## Follow-up on 2026-10-01

An ephemeral Codex CLI probe confirmed the narrow challenge mechanism with synthetic output: one completed command returned a fresh 128-bit marker, a later distinct command started with the exact marker as a literal, both commands completed with exit code 0, and the turn completed. An initial probe did not emit the marker in the second command string. These probes did not invoke AAP retrieval and did not establish advice delivery.

The first attempted AAP probe was stopped by automatic approval review because the advice could have come from a private repository. A local check then confirmed the isolated `/private/tmp` repository contained only a new Git directory and the generated advice response had one literal synthetic statement, `Use pnpm in packages/app.`, 541 UTF-8 bytes, no stderr, and a well-formed response-only challenge. The same command was then approved for the synthetic fixture. One invocation exited before any command. Later invocations produced two command start/completion pairs with exit code 0 and a completed turn. The retrieval command was wrapped by Codex as `/bin/zsh -lc '<exact invocation>'`; its completed output contained the challenge, and the later command output contained the challenge. The observer at that point required the bare invocation and returned no witness. After an exact wrapper rule was added, the final run exceeded 120 seconds and was interrupted. No observer-qualified real AAP exposure or `delivered/host-challenge` fact resulted. No raw transcript or marker was retained in the report.

The implementation now adds a response-only challenge wrapper around public retrieval and a bounded observer for direct `codex exec --json --ephemeral` child events. It accepts only the exact retrieval command or the observed exact shell wrapper; extra shell work is rejected. An attached observer checks the stored bundle, repository, lesson revision, session, context, operation signature and retrieval reference before it can append `delivered/host-challenge`. Imported JSONL and non-Codex child streams cannot mint that witness; public `advice record` remains limited to `agent-claim`. At this implementation checkpoint, the observed-delivery path still lacked a same-child live qualification. The later qualification below supersedes that source status. Application and outcome require their own witnesses.

After the last code change, `rtk pnpm build` exited 0 and the focused command `rtk proxy node --test dist/test/ael-advisory-host-exposure.test.js dist/test/ael-advisory-usage.test.js dist/test/ael-advisory-pilot.test.js` passed 14/14 tests. The full `rtk pnpm check` passed 1051/1051 tests, with zero failures or skips. The first added challenge test and host-origin test each failed before their corresponding implementation changes. These tests verify the local contract and public boundary, not a completed live AAP-A4 run.

## Qualification after integration

Two further controlled runs used the same synthetic repository and `codex-cli 0.157.1`. The first ran the corrected `CodexAdviceExposureObserver` against direct `codex exec --json --ephemeral` child output. It exited 0 after 16.9 seconds with nine parsed events and no malformed event. The retrieval item completed with exit code 0 and contained the response-only challenge; a later distinct command contained that challenge as a literal and completed with exit code 0; `turn.completed` followed. The observer returned a witness binding the thread, both item IDs, response digest and bundle ID. The stored bundle scope and retrieval fact matched. Only hashes, booleans, event types, item status and exit codes were retained.

The second run reset the synthetic fixture and called `attachCodexAdviceExposure` on the direct child. It exited 0 after 19.6 seconds and returned `qualified=true`, `sameChild=true`, `storedHostFact=true`, `retrievedFact=true`. The attached observer wrote `delivered/host-challenge` for the expected bundle and rejected imported event streams by construction.[^attached] These runs qualify this narrow delivery source for the installed CLI version and synthetic fixture. They do not establish that the agent applied the advice, completed the package-manager task, or reduced redundant work. AAP-A4 and AVB-A4/A5 still need those separate observations.

The final commands were `rtk proxy node /private/tmp/aap-exposure-probe/setup.mjs`, `rtk proxy node /private/tmp/aap-exposure-probe/inspect.mjs`, `rtk proxy node /private/tmp/aap-exposure-probe/probe-real.mjs`, then the setup command again and `rtk proxy node /private/tmp/aap-exposure-probe/probe-attach.mjs`. The inspection returned a 541-byte ready response with one literal synthetic statement and a 128-bit response-only challenge. Both model runs were approved outside the default sandbox after that fixture inspection. The temporary scripts, database and raw child stream are not repository artifacts; the sanitized outcomes above are the retained verification record.

After the provenance review, the launcher pinned the installed Codex 0.157.1 binary digest and required the exact `-a never exec` argument form. A final run reset the same synthetic fixture, built the integrated source, and attached both the AEC stream reader and AAP observer to one verified child. `rtk proxy node /private/tmp/aap-exposure-probe/probe-trusted.mjs` exited 0 after 19.8 seconds and returned `verifiedBinaryChild=true`, `qualifiedAdvice=true`, `sameChild=true`, `storedHostFact=true`, `trustedOperationStream=true`, two operation requests and two linked results. The parser retained no raw command, output, transcript or challenge. This qualifies the joint AEC/AAP source path for this pinned binary; it remains a source probe, not an AVB paired trial.[^trusted]

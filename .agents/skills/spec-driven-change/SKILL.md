# Spec Driven Change

## Core principle

An accepted proposal is not implementation authorization. Define and approve the behavior first.

## Workflow

1. Read the proposal and its evidence.
2. Use the Superpowers brainstorming process when design choices remain.
3. Write the specification using `docs/sdd/spec-template.md`.
4. Ensure goals, non-goals, behavior, failure policy, privacy, compatibility and acceptance criteria are explicit.
5. Perform a placeholder, contradiction, ambiguity and scope review.
6. Stop for explicit human spec approval.
7. After approval, use Superpowers `writing-plans` to create the implementation plan.

Do not start implementation while presenting the spec for approval.
